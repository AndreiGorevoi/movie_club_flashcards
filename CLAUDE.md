# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Карточки с вопросами для обсуждения после фильма в киноклубе. Ведущий заводит
фильм и список вопросов, гости по ссылке переворачивают карточки на общем столе,
синхронизированном между всеми устройствами.

Живой сайт: https://movie-club-production-1fa6.up.railway.app

## Команды

Нужен **Node 24+** — сервер использует встроенный `node:sqlite`.

```sh
npm install
npm run build              # tsc -b (typecheck) + vite build → dist/

# Один процесс: API + раздача собранного dist/ (нужен предварительный build)
ADMIN_PASSWORD=dev npm start          # http://localhost:3000

# Два процесса, когда правишь фронт: vite проксирует /api на :3000
ADMIN_PASSWORD=dev npm run dev:api
npm run dev                           # http://localhost:5173
```

Без `ADMIN_PASSWORD` сервер поднимается в режиме только для чтения — все
мутирующие ручки отвечают 503, кнопки правки в UI не появляются.

Тестов и линтера в проекте нет. Проверка типов — единственный автоматический
контроль: `npx tsc -b` (то же, что первая половина `npm run build`).
`tsconfig.app.json` включает `strict`, `noUnusedLocals`, `noUnusedParameters`,
так что неиспользованная переменная валит сборку.

Сервер (`server/*.js`) — обычный JS без типов и без сборки, `tsc` его не видит.

## Архитектура

### Сервер (`server/`)

Один процесс, четыре файла, без фреймворка:

- `index.js` — `createServer`; сначала отдаёт запрос в `handleApi`, всё
  неопознанное уходит в раздачу статики из `dist/`. Ненайденный путь отдаёт
  `index.html` (клиентская маршрутизация). На старте засеивает демо-фильм, если
  база пуста, и предупреждает про отсутствующий `ADMIN_PASSWORD` / Volume.
- `api.js` — маршрутизация регулярками, проверка пароля, валидация входа.
- `tables.js` — общий стол и рассылка событий подписчикам.
- `db.js` — схема SQLite и подготовленные запросы.

`handleApi` возвращает `true`, если путь начинался с `/api/` — это единственный
признак, по которому API отделяется от статики.

### Общий стол (SSE)

Ключевая механика. Каждый открывший фильм браузер держит одно соединение к
`GET /api/films/:id/stream`; сервер при любом изменении пишет туда **целиком**
новое состояние стола (`{ order, flipped, viewers }`), React перерисовывает
сетку. Клиент узнаёт про собственное нажатие оттуда же, откуда остальные:
ответ на `POST /flip` в `useTable.ts` намеренно игнорируется.

Важные свойства, которые легко сломать:

- Состояние стола живёт в таблице `tables`, а не только в памяти, — редеплой
  посреди встречи не закроет всем карточки. В памяти (`subscribers` в
  `tables.js`) только открытые соединения.
- Переворот и закрытие идемпотентны, блокировок нет — Node однопоточный, а
  повторное нажатие ничего не меняет.
- `unflip` намеренно без пароля, как и `flip`: закрывает случайно открытую
  карточку у всех. Пароль на `reshuffle` (обнуляет стол) и `unshuffle`.
- Heartbeat `: ping` раз в 25 с, иначе прокси рвут молчащее соединение.
- Новый стол раскладывается в порядке ввода вопросов; тасуется только по
  кнопке (`reshuffle`), `unshuffle` возвращает порядок ввода, не закрывая
  открытые карточки.
- `ensureTable` пересобирает стол, если число вопросов больше не совпадает с
  длиной `order`. Поэтому `POST /api/films` вызывает `resetTable(film.id)`:
  правка вопросов раскладывает стол заново.
- `viewers` считается как размер `Set` подписчиков, поэтому любое подключение и
  отключение делает `broadcast` — счётчик у всех обновляется сам.

### Индексы карточек — единственная настоящая ловушка

- `order` — перестановка **индексов вопросов** фильма; позиция в массиве это
  место на столе.
- `flipped` — тоже **индексы вопросов**, не позиции на столе.

Отсюда в `Session.tsx`: `key={questionIndex}`, `flipped.includes(questionIndex)`,
`flip(questionIndex)`, а номер на карточке — `position + 1`. Путаница этих двух
систем координат откроет не ту карточку.

### Доступ

Пароль ведущего — переменная окружения `ADMIN_PASSWORD`. Клиент кладёт его в
`localStorage` (`movie-club.password`) и отправляет открытым текстом в
`Authorization: Bearer`. Сессий, токенов и пользователей нет. Сервер сравнивает
sha256-дайджесты через `timingSafeEqual` (хэш нужен, чтобы уравнять длину) и
задерживает неверную попытку на 400 мс.

Проверка идёт на сервере: `requireAdmin` в `api.js` — единственная правда,
`session.admin` на клиенте только рисует кнопки. Переворачивать карточки может
любой без пароля, **перетасовать — только ведущий** (иначе гость обнулит
встречу).

При загрузке `App.tsx` спрашивает `GET /api/session`; если сохранённый пароль
больше не подходит (например, сменили в Railway), он стирается.

### Фронтенд (`src/`)

Маршрутизации нет — `App.tsx` держит `Screen` в `useState` (`films` / `session`
/ `edit`) и сам грузит список фильмов. Дальше:

- `api.ts` — единственное место, знающее про сервер и про пароль в localStorage.
- `useTable.ts` — подписка на SSE-поток и отправка `flip`/`reshuffle`.
- `components/Card.tsx` — `useFitText` подгоняет размер шрифта циклом, замеряя
  `scrollHeight`, и пересчитывает по `ResizeObserver` (поворот планшета, смена
  числа колонок). Угадывать по длине строки нельзя.

### Данные и деплой

База: `${DATA_DIR}` → `${RAILWAY_VOLUME_MOUNT_PATH}` → `./data`, файл
`movie-club.db`. Локальная `data/` в `.gitignore`.

Деплой на Railway по `railway.json` (NIXPACKS, `npm run build` + `npm start`,
порт из `PORT`). **Volume обязателен** — без него файловая система контейнера
эфемерная и база умрёт на первом редеплое; сервер пишет об этом в лог.

Экспорт/импорт: `Backup` (`version: 1`) — JSON со всеми фильмами. Импорт
**сливает**, а не заменяет: знакомый `id` обновляется, незнакомый добавляется,
всё в одной транзакции.

`saveFilm` — одна операция и на создание, и на правку; `createdAt` существующего
фильма не перезаписывается, потому что список отсортирован по нему.

## API

| Метод | Путь | Пароль |
| --- | --- | --- |
| `GET` | `/api/health` | нет |
| `GET` | `/api/session` | нет |
| `POST` | `/api/session` | проверка |
| `GET` | `/api/films` | нет |
| `POST` | `/api/films` | да (create + update по `id`) |
| `DELETE` | `/api/films/:id` | да |
| `POST` | `/api/films/import` | да |
| `GET` | `/api/films/:id/stream` | нет (SSE) |
| `GET` | `/api/films/:id/table` | нет |
| `POST` | `/api/films/:id/flip` | нет |
| `POST` | `/api/films/:id/unflip` | нет |
| `POST` | `/api/films/:id/reshuffle` | да |
| `POST` | `/api/films/:id/unshuffle` | да |

Лимиты валидации (`validateFilm` в `api.js`): тело ≤ 1 МБ, название ≤ 200,
вопросов ≤ 200, вопрос ≤ 500 символов, подпись обрезается до 200.
