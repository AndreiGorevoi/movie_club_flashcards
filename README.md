# 🎬 Киноклуб · Карточки

Карточки для разговора после фильма. Выбираешь фильм — на столе появляются
закрытые карточки, по одной на каждый загруженный вопрос. Кто-нибудь тыкает
любую, она переворачивается, вопрос зачитывается вслух, начинается обсуждение.
Правильных ответов нет — это не квиз.

## Как этим пользоваться

1. **Добавить фильм** — название, необязательная подпись (год, режиссёр, дата
   встречи) и вопросы: по одному в строке. Сколько строк — столько карточек.
2. **Открыть фильм** — колода тасуется, карточки ложатся рубашкой вверх.
3. **Переворачивать по очереди.** Сверху видно, сколько уже открыто.
4. **Перетасовать** — закрыть всё и разложить заново.

Перевёрнутые карточки переживают случайный F5, но забываются вместе с закрытой
вкладкой: каждая встреча начинается с чистого стола.

## Где живут данные

Фильмы и вопросы лежат в `localStorage` **того браузера, где их вводили**.
Сервера и базы нет — приложение целиком клиентское.

Отсюда два следствия:

- **«Скачать копию»** сохраняет все фильмы одним JSON-файлом. Делай это после
  каждого добавления, если не хочешь однажды всё потерять вместе с очищенным
  кэшем.
- **«Загрузить копию»** сливает файл с тем, что уже есть: знакомые фильмы
  обновляются, новые добавляются. Так переносятся фильмы на второе устройство.

Друзья, открывшие ссылку у себя, увидят пустой список — у них свой браузер и
своё хранилище. Обычный сценарий: один экран, который видят все.

## Разработка

```sh
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
npm run start    # раздать собранное на PORT (по умолчанию 3000)
```

Стек: Vite + React + TypeScript. Без UI-библиотек и без зависимостей в рантайме —
`server.js` написан на голом `node:http`.

## Деплой на Railway

1. Залить репозиторий на GitHub.
2. В Railway: **New Project → Deploy from GitHub repo**, выбрать этот репозиторий.
3. Ничего настраивать не нужно — `railway.json` уже задаёт сборку (`npm run build`)
   и запуск (`npm run start`), а сервер слушает `process.env.PORT`.
4. **Settings → Networking → Generate Domain**: получится ссылка вида
   `movie-club.up.railway.app` с рабочим HTTPS. Домен покупать не нужно.

Расход символический: статика плюс крошечный Node-процесс. Если включить
**App Sleeping** (Settings → Deploy), сервис будет спать между встречами и почти
не тратить кредит.

## Структура

```
src/
├── types.ts               Film, Backup
├── storage.ts             весь доступ к localStorage / sessionStorage
├── seed.ts                фильм-пример при первом запуске
├── App.tsx                переключение экранов
└── components/
    ├── FilmList.tsx       список фильмов, экспорт и импорт
    ├── FilmForm.tsx       добавление и правка
    ├── Session.tsx        стол, тасовка, прогресс
    └── Card.tsx           одна карточка и её переворот
```

Если однажды понадобится общая база на всех — менять придётся только
`storage.ts`: остальное приложение знает лишь его функции.
