# 🎬 Киноклуб · Карточки

Карточки для разговора после фильма. Выбираешь фильм — на столе появляются
закрытые карточки, по одной на каждый загруженный вопрос. Кто-нибудь тыкает
любую, она переворачивается, вопрос зачитывается вслух, начинается обсуждение.
Правильных ответов нет — это не квиз.

## Как этим пользоваться

1. Нажать **«Я ведущий»** и ввести пароль — иначе список только для чтения.
2. **Добавить фильм** — название, необязательная подпись (год, режиссёр, дата
   встречи) и вопросы: по одному в строке. Сколько строк — столько карточек.
3. **Открыть фильм** — колода тасуется, карточки ложатся рубашкой вверх.
4. **Переворачивать по очереди.** Сверху видно, сколько уже открыто.
5. **Перетасовать** — закрыть всё и разложить заново.

## Что где хранится

| Что | Где | Насколько долго |
| --- | --- | --- |
| Фильмы и вопросы | SQLite на сервере | Навсегда, с любого устройства |
| Какие карточки перевёрнуты | `sessionStorage` браузера | До закрытия вкладки |
| Пароль ведущего | `localStorage` браузера | Пока не нажать «Выйти» |

Фильмы переживают закрытый браузер, чистку кэша, смену устройства и заход
друзей по ссылке. Стол забывается вместе с вкладкой — каждая встреча
начинается с чистой раскладки, и это сделано намеренно.

**«Скачать копию»** сохраняет все фильмы одним JSON-файлом.
**«Загрузить копию»** сливает такой файл с базой: знакомые фильмы обновляются,
новые добавляются, ничего не затирается.

## Кто что может

Читать и переворачивать карточки может любой, у кого есть ссылка. Добавлять,
править и удалять — только после ввода пароля из переменной окружения
`ADMIN_PASSWORD`. Пароль проверяется на сервере сравнением постоянного времени,
неверная попытка отвечает с задержкой, а запрос без пароля получает 401
независимо от того, что нарисовано в интерфейсе.

Если `ADMIN_PASSWORD` не задан, сервер поднимается в режиме только для чтения и
честно об этом пишет в лог.

## Разработка

Нужен **Node 24+** — используется встроенный `node:sqlite`.

```sh
npm install
npm run build                          # собрать фронт в dist/

# один терминал: API + раздача собранного фронта
ADMIN_PASSWORD=dev npm start           # http://localhost:3000

# два терминала, если правишь фронт (вторым — vite с проксированием /api)
ADMIN_PASSWORD=dev npm run dev:api
npm run dev                            # http://localhost:5173
```

Локально база ложится в `./data/movie-club.db` (папка в `.gitignore`).

## Деплой на Railway

1. Залить репозиторий на GitHub.
2. Railway → **New Project → Deploy from GitHub repo** → выбрать этот репозиторий.
   Сборку и запуск подхватит `railway.json`, порт — из `PORT`.
3. **Variables** → добавить `ADMIN_PASSWORD` со своим паролем.
4. **Settings → Volumes** → создать Volume и примонтировать, например, в `/data`.

   ⚠️ Это обязательный шаг. Файловая система контейнера на Railway эфемерная:
   без Volume база сотрётся при первом же редеплое. Путь искать не нужно —
   Railway сам подставляет `RAILWAY_VOLUME_MOUNT_PATH`, и сервер его читает.
   Если Volume забыт, в логе появится предупреждение.
5. **Settings → Networking → Generate Domain** → ссылка вида
   `movie-club.up.railway.app` с рабочим HTTPS. Домен покупать не нужно.

Один контейнер, никакой отдельной базы: расход по кредиту минимальный.
**App Sleeping** включать можно, но учти — первый заход после сна будет
пробуждаться пару секунд.

## API

| Метод | Путь | Пароль | Что делает |
| --- | --- | --- | --- |
| `GET` | `/api/health` | нет | Живость, число фильмов |
| `GET` | `/api/session` | нет | Включены ли правки, вошёл ли ты |
| `POST` | `/api/session` | — | Проверить пароль |
| `GET` | `/api/films` | нет | Все фильмы |
| `POST` | `/api/films` | да | Создать или обновить (по `id`) |
| `DELETE` | `/api/films/:id` | да | Удалить |
| `POST` | `/api/films/import` | да | Слить список фильмов с базой |

## Структура

```
server/
├── index.js               http-сервер: API + раздача dist/
├── api.js                 маршруты, пароль, валидация
└── db.js                  SQLite: схема и запросы

src/
├── types.ts               Film, Backup
├── api.ts                 единственное место, знающее про сервер
├── storage.ts             состояние стола в sessionStorage
├── App.tsx                загрузка, переключение экранов
└── components/
    ├── FilmList.tsx       список, экспорт и импорт
    ├── FilmForm.tsx       добавление и правка
    ├── Unlock.tsx         вход ведущего
    ├── Session.tsx        стол, тасовка, прогресс
    └── Card.tsx           одна карточка и её переворот
```

Стек: Vite + React + TypeScript на фронте, голый `node:http` и `node:sqlite` на
сервере. В рантайме ноль зависимостей.
